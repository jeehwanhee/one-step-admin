# ADR-001 Firebase, MySQL 분리

- 상태 : accepted
- 날짜 : 2026-10-05

## 상황
한걸음 앱은 firestore를 사용하여 출시되어있는 상태.
관리자 웹은 aws 서버로 구축 예정
db를 어떻게 둘지를 결정해야한다

관리자 웹에서는 소속 청년들의 통계를 보는 것이 가장 큰 기능이기 때문에, join이나 정렬을 많이 사용할 것으로 예상된다

하지만 firestore에는 join이 없고, 컬렉션 기반이며 문서 수만큼 읽기 비용이 발생

## 선택지
**1. firestore만 사용**
앱 수정 없이, 웹 서비스에서도 firestore읽기 사용
하지만 읽기 비용이 증가하고 aws와 gcp 통신이 지연될 수도 있음

**2. MySQL로 이전**
구조가 단순해짐
하지만 앱을 대거 수정해야함

**3. firestore 유지, MySQL 복제**
앱을 수정하지 않고, 별도의 동기화 루틴을 통해 MySQL로 데이터를 복제, 통계낸다.

## 결정
선택지 3을 택한다.

앱은 쓰기가 많고, 앱의 데이터 구조,db를 전면 교체하는 것은 현재 프로젝트의 범위를 넘는 것이라고 판단
관리자 웹에서는 주로 여러 join을 통한 읽기이므로 RDB를 사용

(추후 웹 개발이 끝난 후 MySQL로의 이전을 다시 고려)

## 결과
**얻는 것**
- 앱 수정 안함
- 조희 성능, 집계를 RDB로 구현

**감수할 것**
- 동기화 과정이 필요
- 두개의 db를 동시에 운영해야함

**후속 작업**
- 멱등성 보장
