# ADR-006 인프라 결정

- 상태 : accepted
- 날짜 : 2026-10-07

## 상황
처음에는 AWS만 생각했었는데, 최근 GCP 무료 한도가 있다는 것을 알게되었고, 장기적인 운영을 생각했을 때, vercel과 같은 서비스를 이용할 수 있는지에 대한 의문도 생김
이에 따라 각각의 인프라의 특징을 파악하고 사용할 것을 결정하기 위함

관리자 웹은 트래픽이 많지 않아서 비용이 중요한 고려사항이고, 인증은 JWT를 httpOnly 쿠키에 담기로 했기 때문에 프론트와 백엔드가 서로 다른 사이트(cross-site)가 되면 SameSite 쿠키 제약에 걸릴 수 있다

## 선택지
**1. AWS로 통합 (EC2 + RDS + S3/CloudFront)**
프론트, 백엔드가 같은 오리진이라 CORS, SameSite 문제가 없음
트래픽이 적어도 EC2, RDS는 상시 과금됨

**2. Vercel(프론트) + AWS(백엔드)**
배포 편의성이 좋음
서로 다른 도메인이라 커스텀 도메인 + 서브도메인 구성이 필요해짐(안하면 쿠키 인증이 깨질 수 있음)
Vercel 무료 플랜은 상업적 사용이 금지라 결국 Pro 플랜(유료)이 필요할 가능성이 큼

**3. GCP(Cloud Run + Cloud SQL)**
요청이 있을 때만 인스턴스가 뜨는 구조라 저트래픽 기준 비용이 더 저렴할 수 있음
Spring Boot(JVM)는 콜드 스타트가 느림
동기화 스케줄러(10분 주기)가 인스턴스 내부 스케줄러로는 안 돌아서 Cloud Scheduler로 재구성해야함

## 결정
선택지 1을 택한다.

콜드 스타트 대응, 스케줄러 재구성 같은 추가 공학적 비용을 감수할 만큼 절감액이 크지 않다고 판단
프론트까지 같은 클라우드, 같은 오리진에 두면 쿠키 인증 관련 고민이 사라지는 것도 이유

또한 한걸음 전용 도메인을 구매하여 사용 (연 20000원 내외)

## 결과
**얻는 것**
- 클라우드 하나만 운영
- 콜드 스타트, 스케줄러 재설계 같은 추가 작업 없음

**감수할 것**
- 저트래픽이어도 EC2, RDS 비용이 상시 발생

**후속 작업**
- EC2, RDS 인스턴스 사이즈 결정
- 도메인 구매, Route53 설정
